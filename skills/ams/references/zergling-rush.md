# Zergling Rush

## Consent

Activate only from an unambiguous current-turn user instruction such as:

```text
Use Zergling Rush for this task.
AMS ZERGLING RUSH
/claude-ams:zergling-rush <objective>
```

Stored settings, an old handoff, prior consent, `extreme`, urgency, or a generic request to be fast is not consent. State before dispatch that Rush may use substantially more agents and model usage.

## Behavior

Rush optimizes wall-clock completion and may:

- fill useful safe capacity;
- use stronger routes earlier when that shortens the critical path;
- run competing approaches, duplicate investigations, speculative preparation, and redundant validation with plausible value;
- use one bounded manager layer;
- use Agent Teams when peer communication adds value and teams are enabled;
- use the bundled read-only dynamic audit workflow when workflows are enabled and appropriate.

Rush still requires finite allocation, one writer per surface, explicit ownership, truthful model reporting, normal permissions, independent validation, root acceptance, and coherent evidence custody. It never authorizes uncontrolled recursion, overlapping writers, hidden substitutions, skipped checks, unsafe external actions, or non-root completion.

Cancel speculative or duplicate work as soon as expected value disappears. Do not repeat unchanged failed setups.

Rush consent ends with the current objective. On transition out, stop new Rush-only dispatch, drain useful atomic work, collect evidence, release ownership safely, and continue under the selected normal mode.
